# 03 · Configuração

Pré-requisito: ambiente preparado conforme [Instalação](01.instalacao.md).
Edite o `.env` na raiz do projeto; consulte também o [arquivo de exemplo](../.env.example).
Variáveis já definidas no ambiente têm prioridade sobre o `.env`.

| Variável | Padrão | Finalidade |
|---|---|---|
| `WEBRAG_SOURCE_DIR` | `G:\Meu Drive\ContextDirectory\Web Engineer` | Pasta de Markdown e PDFs |
| `WEBRAG_INDEX_DIR` | `data/index` na raiz do projeto | Destino do índice |
| `WEBRAG_EMBED_MODEL` | `intfloat/multilingual-e5-small` | Modelo de embeddings |
| `WEBRAG_CHUNK_CHARS` | `1200` | Tamanho dos trechos em caracteres |
| `WEBRAG_CHUNK_OVERLAP` | `200` | Sobreposição entre trechos |
| `WEBRAG_CHUNK_MIN` | `400` | Limiar para unir seções pequenas |

Prefira caminhos absolutos ao personalizar as pastas, especialmente para uso via MCP.
Para incluir outras notas, amplie `WEBRAG_SOURCE_DIR`; a primeira pasta do caminho
relativo identifica o pilar usado como filtro.

Após alterar a origem, o modelo ou a divisão dos trechos, siga
[Atualizar o conteúdo](02.uso.md#atualizar-o-conteúdo).
Um modelo diferente precisa estar baixado antes do uso offline; o bootstrap
baixa o padrão, a menos que `WEBRAG_EMBED_MODEL` esteja definido no ambiente do processo.

## Particularidades do WSL

Nos comandos dos guias, substitua `<name>` pelo nome da distribuição desejada,
como `labafero`, `konton`, `quila` ou `asc`. Liste os nomes com `wsl --list --quiet`.
Prepare o ambiente e registre o MCP em cada distribuição em que usar o assistente.

O bootstrap usa o projeto em `/mnt/c/Users/anils/projects/webengineer-rag`
e fixa o índice em `data/index` desse projeto. Se mudar esses caminhos, ajuste
`WIN_PROJECT` no script e o `WEBRAG_INDEX_DIR` do wrapper
`~/.local/bin/webrag-mcp` gerado por ele.
Use o mesmo modelo de embeddings na indexação e nas consultas.
