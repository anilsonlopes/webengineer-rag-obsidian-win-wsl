# 07 · Aplicativo e instalador Windows

O aplicativo usa Python 3.12 x64, Tkinter/ttk, PyInstaller em modo onedir e Inno Setup 6.7.3. O instalador inclui Python e dependências para CPU; o modelo é baixado pelo aplicativo no primeiro uso.

## Compilar

Em um Windows com Python 3.12 x64 e Inno Setup 6:

~~~powershell
py -3.12 -m venv .venv-build
.\.venv-build\Scripts\python.exe -m pip install -r packaging\requirements-windows.lock
.\.venv-build\Scripts\python.exe -m pip install --no-deps --no-build-isolation -e .
.\scripts\build-windows.ps1 -Python .\.venv-build\Scripts\python.exe
~~~

Use -Iscc com o caminho de ISCC.exe se ele não estiver instalado no local padrão. O build executa os testes e verifica os binários com um modelo real, por isso precisa de internet e espaço para o modelo temporário. Os dados pessoais e o índice do projeto não são usados nesses testes.

Saídas:

- dist/WebEngineerRAG/WebEngineerRAG.exe: aplicativo desktop, acompanhado da pasta _internal.
- dist/WebEngineerRAG/rag.exe: CLI e servidor MCP, com a mesma pasta _internal.
- dist/WebEngineerRAG-Setup-0.1.0.exe: instalador distribuível.
- Arquivo .sha256 ao lado do instalador.

Distribua o instalador ou a pasta completa; os executáveis isolados dependem de _internal. O pacote não inclui modelo, notas, PDFs, .env ou índices pessoais. Não há assinatura digital configurada.

## Testar o instalador

Em um usuário Windows limpo, execute:

~~~powershell
.\scripts\test-installer.ps1 -Installer .\dist\WebEngineerRAG-Setup-0.1.0.exe
~~~

O teste recusa uma instalação existente. Verifica instalação, atualização, atalhos opcionais, CLI e preservação dos dados na desinstalação. O smoke test do build abre a interface oculta, indexa um Markdown e um PDF, consulta offline e testa MCP por stdio.

Para testar a interface durante desenvolvimento:

~~~powershell
.\.venv-build\Scripts\python.exe -m webrag.desktop
~~~

Ela usa configuração por usuário; o CLI executado a partir dos fontes continua usando o .env do projeto.

## Releases

O workflow Windows executa em pull requests, acionamento manual e tags v*. Apenas tags publicam releases. A tag deve corresponder à versão em pyproject.toml. Atualize também webrag.__version__ ao alterar a versão.

O instalador é por usuário e não exige administrador. Instalações posteriores usam o mesmo AppId e preservam configuração, modelos, logs e índices. A desinstalação mantém esses dados em %LOCALAPPDATA%\WebEngineerRAG.

## Índices e cancelamento

Cada indexação publica uma geração completa por meio do arquivo CURRENT. Leitores também aceitam o formato anterior, com arquivos diretamente na pasta do índice. A geração atual e a anterior são mantidas; gerações mais antigas são removidas após uma publicação bem-sucedida. Os arquivos do formato anterior não são apagados na migração.

Uma trava de sistema impede indexações simultâneas na mesma pasta e é liberada mesmo se o processo terminar inesperadamente. Cancelamento é cooperativo entre documentos, etapas e lotes de embeddings. Um download ou uma gravação já iniciada precisa terminar antes de o aplicativo fechar.

A busca utiliza o modelo registrado no índice publicado. Alterações nas configurações só passam a valer na busca quando o novo índice é concluído. O processo web iniciado pelo aplicativo escuta apenas em 127.0.0.1:8077 e encerra quando a janela é fechada; uma porta ocupada gera um aviso, sem encerrar outros serviços.
